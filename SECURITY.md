# Security policy

## Supported versions

Security fixes are provided for the latest published release. Older versions should be upgraded before troubleshooting.

## Reporting a vulnerability

Do not open a public issue for a vulnerability. Use GitHub's **Security → Report a vulnerability** option for this repository. Include the affected version, operating system, reproduction steps, impact and any proof of concept.

Reports will be acknowledged as soon as practical. A fix, advisory and credited disclosure will be coordinated when the report is confirmed. Please avoid accessing other people's data or disrupting third-party services while testing.

## Release integrity

Release assets include SHA-256 checksums. Managed executable downloads are accepted only over HTTPS from allowlisted hosts and promoted only after their SHA-256 digest matches trusted release metadata or the pinned FFmpeg manifest.
